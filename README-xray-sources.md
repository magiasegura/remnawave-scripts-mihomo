# Выбор источника Xray для RemnaNode

Ветка `feature/jolymmiles-xray` добавляет выбор `XTLS/Xray-core` или
`Jolymmiles/Xray-core` в оригинальные меню DigneZzZ. Инструкция перехода без переустановки: [README_RU.md](README_RU.md). Это ветка разработки;
рабочие серверы при её создании не изменялись.

## Запуск на тестовой Linux-ноде

Используйте файлы этой ветки, а не команду скачивания из upstream README:

```bash
sudo bash ./remnanode.sh core-update
# Либо весь привычный интерфейс, пункт 11:
sudo bash ./remnanode.sh menu
# Отдельный updater сам ищет установленную ноду:
sudo bash ./remnanode-xray-update.sh
```

Если нода называется иначе, передайте имя через окружение:
`sudo env APP_NAME=custom-node bash ./remnanode.sh core-update`.
Так скрипт использует имя и каталоги уже установленного приложения.
Отдельный updater определяет имя проекта по найденному каталогу, как
и в upstream. При нескольких установках используйте основной скрипт с `APP_NAME`.

Сначала выберите источник: `1` для XTLS, `2` для Jolymmiles, Enter для текущего.
После этого доступны оригинальные номера версий, `M` для ручного ввода тега,
`A/S` для переключения pre-release, `R` для обновления списка и `Q` для выхода.
Добавлены `P` для смены источника и `B` для отката последнего полного снимка.
В основном скрипте сохранён `D` для возврата к ядру из контейнера.
Если GitHub недоступен, меню всё равно позволяет выбрать `B`, `P` или `Q`.

Выбор сохраняется **после успешной установки**. Смена через `P` и выход через
`Q` ничего не устанавливают. В существующих установках без настройки источником
считается XTLS. При `install --xray` источник тоже можно выбрать. В режиме
`install --force --xray` используется сохранённый источник, иначе XTLS;
скачивается последний релиз, включая pre-release, как в оригинальном скрипте.

В этой ветке отключена автоматическая проверка новых версий управляющего
скрипта, чтобы upstream не затёр доработку. Обновление самого
скрипта через upstream-команды по-прежнему может заменить доработку оригинальной версией. Ветка опубликована в приватном репозитории. Перед включением
автообновления настройте доступ к нему и значения `SCRIPT_REPO` / `SCRIPT_REF`. Автообновление можно вернуть в `ensure_latest_script`.

## Файлы, резервная копия и откат

Основной скрипт использует `/var/lib/<имя-ноды>`, отдельный updater использует
оригинальный путь `/var/lib/remnanode`:

| Файл | Назначение |
| --- | --- |
| `xray-source` | Только `XTLS/Xray-core` или `Jolymmiles/Xray-core`, без выполнения shell-кода |
| `xray-version` | Установленный тег релиза |
| `xray-backups/<время>.<суффикс>/` | Снимок до изменения ядра или отката |
| `xray-backups/latest` | Имя последнего полного снимка для `B` |
| `.xray-update.lock` | Блокировка параллельных операций через `flock` |

Снимок содержит бинарник, имеющиеся `geoip.dat` и `geosite.dat`, источник,
тег и `docker-compose.yml`. Отсутствовавшие файлы при восстановлении удаляются.
У каталога резервных копий права `700`: Compose может содержать
секреты. Копии не удаляются автоматически. Следите за свободным местом и
сохраняйте нужные снимки отдельно.

Архив скачивается во временный каталог. Из него извлекаются только `xray` и
известные geodata-файлы. Затем скрипт проверяет запуск `xray -version`. Рабочие файлы
заменяются только после этой проверки и создания снимка. Если в релизе нет
geodata, скрипт оставляет установленные базы. При ошибке обновления, проверки Compose,
перезапуска или проверки работающего ядра в контейнере восстанавливаются предыдущие файлы
и выполняется повторный запуск ноды. Если восстановление не удалось, скрипт выводит путь к снимку,
чтобы можно было восстановить файлы вручную. Коды ошибок сохраняются.

`B` требует подтверждения и восстанавливает весь снимок, включая Compose.
Перед ним создаётся новый снимок: повторный `B` позволяет отменить откат.
После `D` выбранный источник остаётся настройкой будущих обновлений, а нода
использует встроенное ядро. Снимок перед `D` также доступен через `B`.

## Зависимости и ограничения

Нужны Linux, Bash, curl, unzip, flock из util-linux и Docker Compose.
Установка unzip остаётся частью оригинального сценария. Используются стандартные
имена `Xray-linux-<архитектура>.zip` в релизах выбранного проекта.
У Jolymmiles на момент проверки есть ZIP для `64` и `arm64-v8a`;
если файла для другой архитектуры нет, загрузка завершается без изменения ядра.
Релизы: [XTLS](https://github.com/XTLS/Xray-core/releases),
[Jolymmiles](https://github.com/Jolymmiles/Xray-core/releases).

Проверка после перезапуска делает до 30 попыток с интервалом в две секунды. Контейнер должен работать без
перезапуска и без статуса unhealthy/starting, а процесс Xray должен работать
при двух проверках подряд с интервалом в две секунды. Для внешнего ядра проверяются путь
монтирования и SHA-256 исполняемого файла работающего процесса через `/proc`.
В контейнере нужны `sh`, `readlink` и `sha256sum`; если проверка недоступна,
обновление считается неуспешным и запускается откат.

Скрипт меняет Compose только внутри одного сервиса ноды, который находит по
`container_name` или образу `remnawave/node`. Поддержан блочный YAML с короткими
записями томов. Inline YAML, длинные записи томов, quoted/anchored объявления сервисов, табуляция и неоднозначный выбор
сервиса отклоняются с сообщением об ошибке. Другие сервисы сохраняются.
Политика `restart` не влияет на добавление монтирования.
Если ввод закрыт на последнем вопросе, резервная копия и успешный результат сохраняются.
При этом скрипт не проверяет клиентские соединения и совместимость конфигурации Remnawave
с конкретным форком. Первую установку через `install --xray` проверяют до запуска
контейнера; автоматический откат всего процесса первичной установки не добавлен.
Полный снимок ядра при этом создаётся. При SIGKILL или отключении питания
автоматическое восстановление не выполняется, сохранённый снимок остаётся.

## Локальные тесты

```bash
bash -n remnanode.sh
bash -n remnanode-xray-update.sh
bash tests/run-tests.sh
```

`test-xray-source.sh` исполняет реальные функции из обоих скриптов во временных
каталогах. Проверяет источник, точный тег, ошибки API и сети, повреждённый архив,
нерабочий бинарник, установку, полный снимок, автоматический откат после изменения
Compose, ручной откат и его отмену. Загрузки и жизненный цикл контейнера подменены.

`test-xray-menu.sh` исполняет оригинальные меню с GitHub-ответами из фикстур:
номера версий, `P`, `M`, `A/S`, `R`, `Q`, `B` без сети. Также проверяет, что
оба самостоятельных скрипта используют одинаковый блок работы с источником.

Тесты не подключаются к серверам и не запускают Docker. Итоговый протокол:
[TESTING-xray-sources.md](TESTING-xray-sources.md).
